## What went wrong, and what changed

1. **`release.py` would have refused the release.** Its check for local changes in the Chromium checkout ran `git status` before `sync`: right after `bump`, every dependency the new DEPS moves (v8, skia, angle, webrtc) shows as modified. Now the check ignores submodules until the pin is synced, and only then ([f64bbf0](https://github.com/robyroro/project-ghost/commit/f64bbf0)).
2. **`bump` didn't move the Mojo salt** (`build/mojom_message_id_salt`, upstream's `chrome/VERSION` at the pin, which `release.py` checks). It does now ([4045302](https://github.com/robyroro/project-ghost/commit/4045302)); the drill's salt was committed by hand ([9dc2324](https://github.com/robyroro/project-ghost/commit/9dc2324)).
3. **Patch 0027's subject began with a UTF-8 byte-order mark.** Windows PowerShell 5.1 prefixes text piped to a native program with one; `format-patch` encoded it into the subject. Fixed ([7981bac](https://github.com/robyroro/project-ghost/commit/7981bac)), and `patches.py check` now refuses a BOM in any commit message.
4. **`release.py`'s tests depended on the live pin**: they hard-coded `152.0.7977.149` while reading the repository's `CHROMIUM_VERSION`, so every security release would have broken them. They follow the pin now.
5. **The runbook named `release.py verify --tag`**, which doesn't exist: `verify` takes a directory. The runbook and the issue's checklist now say to download the draft with `gh release download` and verify that directory, which also checks what people download rather than what's on the build machine.
6. **Triage:** Extended Stable's post for .158 lists no fixes; the CVEs are in the week's Stable post. The runbook and the issue now say so. Nothing in .158's post or the matching Stable post said a fix was exploited in the wild, so the deadline was 72 h.
7. **The phone wasn't notified** of the PIN: desktop notifications reach a phone only with the app's Remote Control on. GitHub's email for the issue arrived (it said "because you commented": whether a bot-opened issue alone notifies depends on the repository's watch setting, which the maintainer checks).

## Where the time goes, and what to try next

- **The development build is the largest single cost, 8 h,** and it runs after the official build. Two options, to measure at the next release: build `out/vanilla` with the new pin right after `bump`, before tagging, while CI runs (it doesn't need the tag); or keep `out/vanilla` tracking upstream's Extended releases nightly, so it is mostly built when a release comes. Running both builds at once is not an option on 32 GB: `chrome.dll`'s ThinLTO link alone left 0.8 GB free at the first official build.
- **The PIN waited 5 h 34 min overnight.** The runbook now says to be at the machine when the tests end. Moving `sign` before the tests is not an option: nothing is signed before it passed.
- **A V8 roll is expensive in both builds.** This release moved V8, Skia, ANGLE and WebRTC; at the pin move from .140 to .149 (V8 roll), the development build alone took 4 h 39 min.

## What differed from a real release

- The test signing identity, and a draft: the name's trademark gate is open.
- No rollout: the update server isn't deployed (sub-project C).
- No update test from `152.0.7977.149-4`: it predates the name Shade and installs under `ProjectGhost`. The development end-to-end update test passed on 2026-10-09.
